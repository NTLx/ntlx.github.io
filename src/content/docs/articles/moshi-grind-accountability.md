Anekha Sokhal 在 AI Engineer New York 的台上给 edge 下了个定义：比别人先知道，知道自己的盲点，有信念把仓位加上去。

前两条是信息问题，第三条不是。

她是 Moshi 的创始人。这家公司给机构交易员做「24 小时量化分析师」，她给产品的比喻是彭博、Claude 和 Netflix 生了个孩子。想想也说得通：彭博是那张每天要盯的桌子，Claude 是能对话，Netflix 是推荐系统——你盯着原油的时候，其实现在就需要天然气和航运股的二阶、三阶导。

比喻好记，也容易把人带偏。Latent Space 这期 26 分钟的对话里，比它更值得记的是她收尾时留下的那个问题：如果 edge 真的活在人的脑子里，机器到底能捕获多少？她的回答是我们还没有答案。

我的判断是，Moshi 卖的不是这个答案，是答案之前的那一段。这一段之所以能卖，靠的不是模型多强，是一条模型变强也推不动的线。

![文章核心信息图：左侧是机器承担的可审计苦工，右侧是人保留的认账判断](https://cdn.jsdelivr.net/gh/NTLx/Pic@master/wechat-articles/2026-10-22-moshi-grind-judgment-img-00-infographic-core-summary.png)

## 她把 edge 定义成一个下载不到的东西，然后开始卖下载器

演讲里有一段推理很干净。她说，如果所有人都有同样的模型、同样的 skills 文件、同样的 MCP 连接器、同样好的提示词，那 edge 是什么？剩下的只能是那些下载不到的东西：几十年坐在最好的交易员旁边攒下来的上下文，而且会跟着这个人换公司、退休一起走掉。

这段话其实说清了产品该做什么、不该做什么。

紧接着就有个裂缝。Moshi 干的恰恰是把这些上下文显性化，清洗、打标、建本体、塞进一张连通的图，然后推到你眼前。她给的数量级是四秒钟里学到 300 件新东西，累计 24 亿个数据点。

如果 edge 的本质是「下载不到」，那一个以推送为核心交互的产品，捕获的是 edge，还是 edge 的原料？

她自己大概知道这里说不圆，所以收尾时把问题交了出来，没给结论。这句话比整个产品叙事更值得信。不是因为它谦虚，是因为它准确：一个人愿意在台上说「这部分我不知道」，通常说明她清楚哪部分是知道的。

## 模型会变强，认账不会

她给「人留在环里」的理由，最容易被读成能力论证。

她也确实用了一次：人脑功率大约 20 W，860 亿个神经元，而要模仿其中一小片的系统需要一座电厂。这个对比抓人，但撑不住她的结论。效率论证可以被推翻，电厂算得更多、更快、不睡觉，明天的电厂还会更便宜。如果理由只是「机器笨」，这条线就会随着模型升级一路后退，退到没有线。

她真正给出的理由在别处，硬得多。

交易的另一边是人。是客户，是一船实货，是一整个团队。出事的时候得有人站出来说，我基于什么理由做了这个决定。她把这段讲得很具体：一个 agent 泄露了你的 API key，它只会说「抱歉，我不该这么做，请轮换一下」。这句话在工程上完全合理，在金融里完全不够。

![责任边界：机器吐出道歉，人按下印章](https://cdn.jsdelivr.net/gh/NTLx/Pic@master/wechat-articles/2026-10-22-moshi-grind-judgment-img-01-comparison-accountability.png)

这条线不是划在能力上，是划在认账上。

它耐用的原因很简单。模型变强，不会让「谁认账」这个问题变得更容易回答。边界不动，建在它上面的产品就不用每年重新论证自己为什么存在。

对做 AI 产品的人来说，这比「我们的模型更强」耐用得多。别去找「模型还做不到」的缝隙，那种缝隙会被填平；要找「能力提升也推不动」的边界，比如责任、授权、后果归属。这类边界通常不在技术里，在制度里。

适用范围得说清楚：它在人对人的顾问和交易关系里成立。纯自营、可完全回测、盈亏自负的策略里，这条线已经很细了，高频做市早就把报价交给了算法。把它当成金融业的普遍规律，会读错。

## 她卖出去的是可审计的苦工

剥掉比喻，Moshi 的产品结构其实很朴素，而且我认为比她自己的说法更可信。

官网的口号是「金融不缺数据，缺综合」，比「新彭博」准确。她拆的数据也确实是一个交易员真会拆的：期货时间序列和技术指标，基本面的供需，新闻和 X 上的碎片，最后一层是用户自己的私有数据——你信任哪几个分析师、你订了什么、你司那个专门数霍尔木兹海峡 LNG 船数的人。

往下看，有三个工程决定值得单独记。

头一个是分歧即信号。路透说一套、彭博说一套、华尔街日报说一套，三家不一致。她说，不一致本身就是数据点，因为没人知道，而没人知道的地方可能有价差。在所有人都能拿到同一个模型的年代，来源之间的分歧就是剩下的信息。

第二个是给噪音打置信度，不假装它干净。大宗商品领域里，LNG 设施的运营方会直接在 X 上发状态更新，那是最快的通告方式。这类信息不该被当成新闻，也不该被扔掉。她的处理是标一个分数，再把分数背后的证据一起摊开。

第三个是自建还是采购，她没给技术答案。第一顺位是数据：别人把数据交给我们，我们不想再转手给第三方。第二顺位是人：没有工程团队就用现成的，有团队他们就想自己造。她没有假装这是道技术判断题，这就比大多数 build vs buy 的讨论诚实。

这里有个对照我一直觉得有意思。她是一篇 ICLR 2026 论文的共同作者，论文测的是视觉基础模型的三维几何推理，结论相当不客气：当前模型在心理旋转这类需要细致几何区分的任务上明显失败，判断面几何、凸性、复合结构这些基本属性时准确率低得离谱。而 Moshi 的文档解析层，用的正是视觉语言模型去读客户那些乱七八糟的 PDF。

看着矛盾，其实不矛盾。读 PDF 版面是二维结构还原，不是三维几何推理。但更有意思的是她为什么敢这么用：那一层的错误当场就能被抓到。表格串行、数字错位、单位丢失，人一眼看得见。她把模型放在了失败可见的地方。

![访谈画面：Moshi CEO，前能源交易员](https://cdn.jsdelivr.net/gh/NTLx/Pic@master/wechat-articles/2026-10-22-moshi-grind-judgment-img-02-scene-episode-frame.jpg)

顺带一提，公开材料的数字口径还在漂移，演讲里是六个确定性 agent，官网写的是四位专家加一位整合经理。早期产品这样很常见，不必当把柄，但它提醒我别把任何单个数字当成结论。

## 错了会不会被发现，才是能不能交出去的标准

「苦工给机器，判断留给人」这个切法好听，用在工程上会出事。因为「辛苦」是主观的，而团队里最辛苦的活，往往是最需要判断的那部分。

我认为更可靠的判据是可检测性。

读 PDF、对齐时间序列、交叉核对三个来源、盯盘面找异常，这些活错了能被发现，而且往往很快。判断仓位大小、判断这次供给中断会不会持续、判断对手方是不是在骗你，这些错了要过很久才知道，还未必分得清是判断错了还是运气不好。

可检测的活可以交出去，因为你能为它建一条反馈路径。不可检测的活交出去，等于把反馈也一起交出去了。

![反馈回路的长短：短回路上错误立刻被看见，长回路上错误很久才浮现](https://cdn.jsdelivr.net/gh/NTLx/Pic@master/wechat-articles/2026-10-22-moshi-grind-judgment-img-03-flowchart-detectability.png)

这条判据能解释 Moshi 的不少设计选择，也解释了为什么它的语言模型只在呈现层。相关性分析走的是统计、市场结构和领域知识这类确定性方法，语言模型负责把结果写成一段人能读的话。呈现层的错误，读者当场就能发现；分析层的错误，只有确定性方法兜得住。

这也是我一直觉得「用 AI 替代分析师」这句口号没信息量的原因。能被替代的从来不是分析师，是可验证的那部分工作。

## 效率账要算两遍

演讲里最不像产品介绍、却最重要的一段，讲的是学徒制。

在投行或者基金，你坐在一个交易员旁边，一只耳朵在桌上，一只耳朵在外面，靠日复一日的浸没把判断力长出来。她说，如果以后每个人都做一人 pod，下一代人的上下文从哪里来。她把这句话放在「现在没人定价的真实成本」的位置上。

播客里还有这件事的另一个版本，对象换成了工程师。她说这次大会上很多 AI 工程师被管理层压得喘不过气，因为管理层讲：我们不需要团队，你就是团队。紧接着那句我认为整期节目最扎人的话——我得一个人把这套系统搭出来，而这套系统通常是十个人做的。

两个版本是同一个结构：效率提升吃掉了生产专业能力的管道。

![学徒制管道：一排交易桌的传动带，到一人一桌处断开](https://cdn.jsdelivr.net/gh/NTLx/Pic@master/wechat-articles/2026-10-22-moshi-grind-judgment-img-04-scene-apprenticeship.png)

另一端有多拥挤，她给了个数字。一个岗位开放四天，收到 2500 份申请，噪音里混着签证问题、暗中求职，还有来刺探的。

这里有个反方值得认真对待。学徒制本来就低效，很多所谓的隐性知识，可以从 transcript、日志、复盘会里重建。如果真是这样，管道断了也不要紧，知识只是换了载体。

我的回答是，可重放的是决策痕迹，不可重放的是「当时为什么犹豫」。犹豫一般不会写进日志，它出现在两个选项都说得通、而你手上只有十分钟的时候。那种东西只能靠坐在旁边，看一个人怎么在不确定里做选择，慢慢沾上。

所以效率这笔账要算两遍。一遍算这个季度省了几个人，一遍算五年之后还有没有人能做出判断。第一遍算得清，第二遍没人算。

站内早前写过一篇[《Claude Code 把专家重新暴露出来》](https://ntlx.github.io/articles/claude-code-expertise)，从另一面切同一个问题：AI 没有把专家抹平，反而把「定义问题、验收结果」重新推到了台前。Moshi 的划线方式是那个结论在金融里的一个具体版本，只是它多了一个前提，那个专家背后原本站着十个人。

## 如果只从这期节目里拿走一条

我会拿这条：去找那条能力提升推不动的边界，然后把自动化压在失败能被当场发现的层。

两条合起来是个挺朴素的工程判断。不是问模型能做什么，是问错了以后谁会知道、谁会认。

Moshi 的答案是，让机器把苦工做到可审计，让人留着认账的资格，并且把认账当成产品的边界，而不是产品的缺陷。她说 Moshi 不是你，也不是一个模型，而是「加强版的你」。这个说法修辞过头了。更准确一点：你原来有十个人的支援，现在有一个不会累、可以被追问、但不能替你签字的支援。

模型的曲线还会往上，苦工的报价还会往下。认账这部分，暂时没有曲线。

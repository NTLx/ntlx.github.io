# 材料理解合同

本文件定义需要深度理解时的认知质量，并给出一个封闭的按需理解候选清单；候选是可选项，
理解本身始终由 Main 直接对 Primary Source 完成。
目标是把 `materials.md`、`blog-memory.md` 和用户意图压缩成一份能直接
指导写作、视觉理解和边界声明的 `understanding-brief.md`。

## 什么时候需要

所有策略在写作前保留 brief 并通过 Understanding Gate。`reader-response` 展开论证；
`tutorial` 聚焦实际操作、验证与适用条件；`news-digest` 聚焦事实、事件关联和不确定性。
深度和标题随策略与材料调整；每篇都需覆盖证据、中心判断、边界和写作应用。

## 输入

- Main 直接读过的 Primary Source 正文；不可用时说明缺失并阻断依赖该内容的判断；
- `posts/{date-slug}/materials.md`；
- `posts/{date-slug}/blog-memory.md` 或 `blog-memory.json`（若已生成）；
- 用户要求、目标读者和限制；
- 当前 strategy、已有 artifacts、上一 Gate 结果；
- 当前任务实际可用的研究或理解能力；候选清单是封闭的，清单外不再新增 understanding 能力目录。

先回答“当前真正的认知缺口是什么”。Main 可以原生完成；确实需要结构化方法时，只允许从封闭的按需候选
清单中选择：`ljg-structure`（母题结构；支持 `read-only`，不写文件）、`ljg-paper`（论文重建）、
`ljg-constraint`（约束与解空间）。候选是可选项，可用不构成调用理由，清单之外不再维护 understanding
能力目录。只有能改善某个具体缺口的调用才保留。没有缺口时 `no-skill` 是合法结果。任何候选输出都必须
经过二次判断，不因报告很长或命令成功就写入 brief。清单约束的是新的调用，历史 brief 里已有的候选
署名不追溯。

## 质量标准

合格的 brief 应让一个不了解过程的写作者知道：

- 材料说了什么，哪些是直接证据，哪些是推断或作者观点；
- 文章真正要回答的核心问题是什么；
- 中心判断是什么，它依赖哪些前提；
- 关键概念、生成机制或因果链如何用读者能理解的语言解释；
- 哪些约束是事实、规则、解释或自设边界，哪些仍不确定；
- 最强反方是什么，中心判断在哪些边界内成立；
- 哪些判断值得进入正文，哪些只应留在材料；
- 材料中有重要可复用 source evidence 时，交代其含义和边界；视觉节点不是必填项；
- 写作契约如何把以上判断转成章节、证据和行动。

## 可核验事实的复核与事实账本

材料中凡涉及**可证伪断言**——数量、时长、倍数、时间线、状态承诺（已经 / 即将 / 都 / 全部 /
唯一 / 首个）、反事实基线（本可以 / 本来需要 / 从一个 X 压缩到 Y）、跨源同一性（X 与 Y 是
同一件事）——在冻结判断前必须回到**当前**一手来源逐条核对，不能沿用研究早期或二手报道留下的
结论。时间敏感状态（「已公开 / 未公开」「已发布 / 未发布」「当前版本」）同样属于此类。

- 一手来源与二手来源冲突时，以**当前**一手来源为准；并在材料中显式记录核对时间
  与来源 URL，让后续写作和 Gate 能复核该断言的新鲜度。
- 网页提取工具可能丢弃按钮、CTA 等结构元素，因此「是否公开 / 是否提供 / 是否有
  链接」这类断言必须回到页面**原始 HTML 或存档快照**核对，而不是依赖提取后的正文。
- 语义提取会丢时间线：原文只在正文里出现过的年份以正文为准，不用推断补足。同一页面
  的不同抓取版本若给出互相冲突的时间，**删除该争议数据**，不要挑一边写进文章。
- 若无法在冻结判断前完成复核，把该断言降级为「未确认」，不要写成已确认事实。

**事实账本**（`## 允许援引的事实`）是这份 brief 的必需内容领域，也是正文、标题和
frontmatter `summary` 唯一允许援引的有量纲事实清单。每条一行，claim 侧写文章将使用的
说法，来源侧三选一：

- `<说法> ← "<来源原文片段>"（<来源>）`——片段必须可直接检索，不得转述，也不得把回译
  后的中文当成原文；
- `<说法> ← derived: <推导式>`——只用于算术、单位换算、时间差等可复算的推导
  （例：「十二年后」← derived: 2014 → 2026）；推导不是来源，不能承载来源才有的断言；
- `<说法> ← rhetoric: 不承载事实`——仅用于修辞性用法（例：「几小时的排查还是几周的
  悬案」）。该短语会被从 claim 扫描中排除，因此不得用来掩埋一条真断言。

正文出现账本未覆盖的可证伪主张时，只能改写该主张，或先在账本里登记来源片段，不能放着
不管。没有外部一手来源、或本策略确实不产生可证伪断言的，写一句说明判断依据即可，不以
空标题伪装完成。

覆盖由 `validate-claims.mjs` 在 Step 3 冻结前检查。它证明**覆盖**，不证明**真假**：
伪造的来源片段同样会通过，claim 与来源的对账仍是 Main 的责任。

## 输出契约

保存为 `posts/{date-slug}/understanding-brief.md`。Gate 要求五个内容领域非空，
接受表达相同领域的标题及不同标题层级；以下是可用的最小结构：

```markdown
## 证据
说明材料来源、实际验证结果，以及证据与推断的区别。

## 中心判断
说明文章回答什么、为什么这个判断成立。

## 边界
说明适用前提、限制和仍未确认的内容。

## 写作应用
说明如何把以上理解转成正文、工程步骤或观察点。

## 允许援引的事实
逐条登记正文可援引的有量纲事实；每条给出来源原文片段、derived 推导式或 rhetoric 标记。
```

reader-response 可按需展开核心问题、机制和反方；news-digest 说明事实核验、
事件联系和不确定性；tutorial 可用「工程目标 / 适用范围 / 工程步骤」表达相应
领域，聚焦实际证据、过程和验证。证据、中心判断、边界、允许援引的事实和写作应用
均不可空缺，但不要求统一七节模板、列表形式或固定条数。不存在相关边界时说明判断依据，
不以空标题伪装完成。

Main 检查是否真正理解、证据能否支撑判断、正文是否兑现承诺。Gate 仅检查内容领域
是否提供，不能证明语义质量。原创要求见 [originality-policy.md](originality-policy.md)；
教程忠实解释工程过程即可，不必凑独立观点数量。

### 可选视觉语义上下文

需要时可说明复杂关系、原图证据和边界，但不必列视觉节点，也不规定插图数量、
位置或形式。Step 4 将最终文章交给视觉 Skill；正文插图由
`baoyu-article-illustrator` 分析，最终图片引用落在 `visual-draft.md`。
契约用短句表达可执行的写作意图，避免复制分析报告或登记工具调用。

## Gate 与改道

完成后运行：

```bash
bun run .agents/skills/wechat-article-write/scripts/validate-understanding.mjs <date-slug>
```

Gate 失败时先看具体缺哪一项：修材料、补证据、缩小中心判断、改变输出
结构，或重新选择能力。不要无条件重复上一条调用，也不要因某个可选
Skill 缺失而阻断整个工作流；只有当前 brief 满足合同，才进入写作。

在 Step 3 为未覆盖的 claim 补登记账本后，**只重跑 `validate-claims.mjs`**，不要重跑本节的
understanding Gate：`markStepDone` 会把 `last_complete_step` 置为 1，而 `Math.max` 只在已有
发布活动时生效，重跑会把一篇进行中的文章从 Step 3 打回 Step 2。只有真正退回 Step 1.8 时才重跑。
